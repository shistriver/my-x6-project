## bugfix：恢复草稿未重置缩放
- 现象：`GraphEditor.loadDraft()` 复用 `importJSON()`，后者收尾是 `zoomToFit()`（适配），不是重置 100%；切换地图路径在 UI 侧额外补了 `ed.transform('zoomTo')`，但两处恢复草稿（手动按钮 / 启动自动恢复）漏了 → 恢复后停在 zoomToFit 比例。
- 修法：在 `loadDraft()` 内 `importJSON()` 之后补 `this.transform('zoomTo')`，一处覆盖两条调用路径（符合"画布能力封装在类里"约定）。zoomTo 是视口操作不污染撤销栈。
- 验证：`npm run build`（vue-tsc -b + vite build）通过。

## 组 hover 高亮边框间距 16→2px
- 用户反馈 hover 组的蓝色虚线框离最外层节点太宽。间距来自组容器 padding，两处 `const pad = 16`：`groupSelection()`(建容器初始值，随后被覆盖) + `fitContainer()`(最终生效，节点变动/组合后重算)。hover 虚线框就是容器 body/stroke，故框↔节点距离 = pad。
- 选方案 A（直接改数值）：两处都改 `pad = 2`。注意 pad 同时是"点击空白选整组"的热区，≤4 会点不中；成员之间的间距是节点自身坐标排布，与此无关。
- 验证：`npm run build` 通过。

### ⚠️ 文字节点拖入不紧贴的真凶：fitTextNode 里错误的 /zoom 换算
- 现象：用户反馈从左侧拖入文字节点仍不紧贴内容（导入路径已修的前提下）。
- 根因：`fitTextNode` 用 `const zoom=graph.zoom()` 把测量结果 **除以 zoom**。但 canvas `ctx.font=fontSize px` 测出的就是**节点局部坐标**下的文字尺寸（X6 的 zoom 是套在外层的 transform scale，不改节点内字体的局部 px 值），节点 width/height 也是局部坐标——同坐标系直接相加，**不该除 zoom**。实测同文字 "Text content"：zoom0.5→节点182(文字仅81.6)、zoom1→91、zoom2→45.5(比文字77还小溢出)。
- 修复：删掉 zoom/k，`newWidth=Math.max(width+TEXT_PAD_X*2,30)`、`newHeight=Math.max(height+TEXT_PAD_Y*2,24)`。导入路径 importJSON 也复用此方法，一并修好（导入时当前 zoom 非 1 同样会错）。
- 实机复验：程序化走 Dnd 拖入（startDragCreate + 派发 mousemove/mouseup），zoom=0.5/1/2 三种下节点均稳定 91×24。build 通过。

### ⚠️ 文字节点还差几像素不贴：canvas.measureText vs SVG getBBox 度量不同
- 现象：属性面板显示 Text content = 89×24（用户机）/ 91×24（本机），但文字 SVG 真实渲染只有 78.6×16，四周留白偏大，视觉上"没紧贴"。
- 根因：`measureTextSize` 用离屏 canvas `ctx.measureText` 估算，与 SVG `<text>` 渲染是**两套字体度量**（同 "Text content" 14px sans-serif：canvas 82.3px、SVG getBBox 78.6px），canvas 偏大约 4px，且不同机器偏差不一致。
- 修复：`measureTextSize(..., node?)` **优先读真实 DOM** 的 `node.findView(graph).container.querySelector('text').getBBox()`（与渲染同源、零误差），返回 `fromDom` 标记；读不到才回退 canvas。
- ⚠️ 时序坑：拖入落图（node:added）/ 导入 JSON（fromJSON）当下 view 里 `<text>` **尚未渲染完**，getBBox 读不到 → 回退 canvas。解法：fitTextNode 里 `!fromDom` 时用 `requestAnimationFrame` 排队下一帧重 fit（实例字段 `pendingTextFitIds: Set` 去重、rAF 内校验 cell 仍存活）。属性面板改文字时 view 已就绪，同步就能读到真实 bbox，无需重试。
- 实机复验（等 2 帧后测）：拖入单行 87×24(文字78.6)、多行 94×34(文字85.9)、zoom0.5→90、zoom2→86、导入"Hello"→41(文字32.8)。全部左右/上下各留 4px（TEXT_PAD_X=4/Y=2），精确贴合。build 通过。

### ✅ 文字节点"没紧贴/越改越大"终极修复（上一轮 padding 才是真凶）
- ⚠️ 用户连续 3 轮反馈没解决：89→91→93，越改越大。**根因其实是最朴素的 `TEXT_PAD_X=4/TEXT_PAD_Y=2`**——节点宽 = 文字宽 + 左右各 4px，canvas/DOM 测出来都约 85px、+8 后就是 93。用户要的"紧贴" = 节点宽 = 文字渲染宽，**根本不该加 padding**。前面几轮纠结 canvas vs DOM、/zoom 都是次要因素。教训：用户说"没紧贴"时先查 padding/边距常量，别一头扎进测量精度。
- 最终方案（GraphEditor.ts）：
  - `TEXT_PAD_X=0, TEXT_PAD_Y=0`；宽度 = 文字 bbox 宽（完全贴），高度 = bbox 高 + 最小 `fontSize*1.4`（防 tspan 的 dy=0.3em 下移 + SVG overflow:hidden 裁掉底部），不再是死板 24。
  - `fitTextNode(node, retry=true)`：真实 DOM bbox 优先，读不到/内容或字号变了就 rAF 下一帧用 `retry=false` 重算一次（防递归）。
  - `measureTextSize` DOM 校验必须确认 `<text>` 渲染的是**当前内容+当前字号**：normalize 去所有空白（多行 \n 渲染成多 tspan、textContent 无 \n，且 &nbsp;=\u00A0）；再比对 `font-size` 属性（面板改字号时内容不变，只比内容会读到旧字号 bbox → 节点不跟随变宽）。两条任一不符→回退 canvas + rAF 重试。
- 实机复验（getSize vs 文字 bbox）：拖入 79×20(78.6×16)、多行 86×30(85.9×30)、字号14→20→111×28(110.3×22)、20→12→68×17(67.4×14)、改文字"短"→14×17(14×14)。全部精确贴。build 通过。

### ✅ 文字节点换行场景修复（用户截图：文字竖排溢出、选中框还横扁）
- 现象：多行文字（属性面板 textarea 回车换行）节点没有跟着变高，文字溢出成竖条，框仍是单行尺寸。
- 根因：`measureTextSize` 的 DOM 校验用 `normalize = s.replace(/\s+/g,'')` **抹掉了换行符**。X6 把 `\n` 渲染成多个 `<tspan>`、`textContent` 无 `\n`，于是「旧的单行 DOM」和「新的多行内容」归一化后都是 `Textcontent` → 被判为有效 → 读到旧单行 bbox 且 `fromDom=true` → `fitTextNode` 跳过 rAF 重测 → 节点永远停在单行尺寸。
- 修复（GraphEditor.ts）：
  1. `measureTextSize` 改为**按 `<tspan>` 逐行比对**：`normLine` 只把 `\u00A0`→空格、折叠行内连续空格并 trim（**保留行数/行序**）；`wantLines=text.split('\n').map(normLine)`，`domLines=tspans.map(normLine)`（无 tspan 时用 `textContent`）；两者行数相同且逐行相等才算 DOM 内容有效。字号校验不变。
  2. `fitTextNode` 在 `resize+translate` 后，若节点仍被选中则调 `syncTransformWidget()` 重建变换框（X6 Transform 不随 resize 自动刷新，否则文字变高后框还横扁）。
- 实机复验（Playwright，草稿注入 + 恢复 + 属性面板改文字）：单行 `Text content` → 79×20；改成 11 行（每字符一行）→ **10×156**，真实 `<text>` bbox 9×156、11 个 tspan，完全贴合；多行 JSON 直接导入同样 10×156。build 通过。
- 教训：校验「DOM 是否已是最新内容」时，**绝不能用 `/\s+/` 抹掉换行**——多行渲染成 tspan 后 textContent 本身就没有 `\n`，再抹空格就会把「行数不同」的两份内容判成同一份。
