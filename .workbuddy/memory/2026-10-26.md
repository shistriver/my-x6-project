## 图层层级：修复置顶/置底 + 新增置上一层/下一层
- 需求：①修复「置于顶层/底层」有问题的 bug；②新增「置上一层 / 置下一层」单步上下移。
- 根因（旧实现）：`changeZIndex` 直接对"直接选中"的 cell 设 `setZIndex(9999/0)`。当选中项是**组合成员**时，它渲染在组容器的 `<g>` 内，自身 zIndex 无法越过其他顶层组，导致置顶/置底看起来无效；且固定 9999 在多选/后续新增元素时易错位。
- 新实现 `changeLayer(action: 'front'|'back'|'forward'|'backward')`：
  - 把每个选中项逐级上溯到**最外层祖先**（无父的顶层 cell）作为"单元"，组合成员→整组一起动。
  - 取所有顶层 cell，按当前 zIndex 升序排成序列；按动作重排（front/back 整块移到头/尾；forward/backward 单元与其上方/下方紧邻的非单元交换，整组上/下移动一层）。
  - `batchUpdate` 内依据新顺序紧凑重分配 zIndex 为 0..n-1，规避固定值与间隙问题。
- HomeView 右键菜单：新增 `forward`(置上一层)、`backward`(置下一层)，与 toFront/toBack 并列；`handleMenuSelect` 改用 `ed.changeLayer(...)`，移除旧的 `changeZIndex` 调用。

## Ctrl/Cmd 多选 bug（选区覆盖层吞事件）
- 现象：先选中大矩形，再 Ctrl+点它内部的房间 → 选区被清空（房间也没选上）；反向（先选房间再 Ctrl 点矩形）同样选不上。
- 根因（读 X6 源码 + headless 实测）：节点一旦被选中，X6 在其 bbox 上盖一层 `.x6-widget-selection-box` div（`pointer-events: auto`）。
  - 覆盖层内的其它节点收不到 cell:mousedown / cell:mouseup；
  - 插件 `onBoxMouseDown` 对「选中框 + ctrl + mousedown」直接 `unselect` 被框住的 cell → 选区被清空；
  - 反向场景被插件 `movedMap` / `selectCellOnMoved: false` 判定挡掉。
- 修复（`GraphEditor.bindCtrlMultiSelect()`）：容器上**捕获阶段**监听 mousedown/mouseup，ctrl/cmd + 左键命中节点就 `g.select`/`g.unselect` 并 stopPropagation（吞掉配对的 mouseup 防二次取反）；未命中节点完全放行。
  - 命中判定 `findNodeAtClientPoint()`：用 `document.elementsFromPoint` 跳过 `.x6-widget-selection` 覆盖层，再 `findViewByElem().cell`；**不要用 `graph.findViewsFromPoint`**（按 bbox 命中且吃画布局部坐标，三栏布局下偏移）。
  - `preventDefault` 会阻止容器获焦（Keyboard 插件 global:false 依赖焦点）→ 必须补 `this.container.focus({ preventScroll: true })`，否则 ctrl 点完按 Delete 失效。
- 验证（playwright-core + chromium-1234 无头驱动真实鼠标）：矩形+3 房间，ctrl 逐个加选/再点取消、反向加选、多选整体拖动、框选、space 平移、Delete 均正常。

## 回归修复：点击后节点跟随鼠标（bindPointerSelection）
- 现象：上一版在 `mouseup` 捕获阶段对"普通点击穿透改选"调 `e.stopPropagation()`，但点击覆盖层时 X6 已在 `mousedown` 启动了"拖动整组"（选中框 div 的 box mousedown），被挡掉的 `mouseup` 传不到 X6 挂在 **document** 上的结束监听器 → 拖动永远不结束 → 节点跟着鼠标跑。
- 修复：把穿透改选从 **mouseup 移到 mousedown** 拦截——判定要改选底层节点时，**mousedown 阶段就** `preventDefault()` + `stopPropagation()`，X6 根本不启动那条拖动；mouseup 只在"已接管"时吞掉配对事件。
- 接管条件（两分支都要求底层确有可改选节点）：① Ctrl/Cmd+左键 → 多选切换；② 普通左键 **且落点在"别的已选节点的选中框覆盖层"+底层节点不在当前选区** → 改选该底层节点。其余（普通选中、拖动节点、拖选中框、缩放/旋转手柄、框选）全部放行。
- 验证（real mouse，1400x900）：选矩形→点内部房间/椭圆均改选 ✅；拖矩形位移60,50且选区=矩形 ✅；点击无拖后坐标不变 ✅；松手后无按键移动鼠标不带动节点 ✅。
- 关键：判定 `onOverlay` 用 `e.target.closest('.x6-widget-selection')`；`isInSelection` = 节点已选中 或 是已选组合容器的后代（保持整组语义）。

## Bug：点 Circle 选中了但"看起来没选中"（Selection 与 Transform 错位）
- 现象：矩形选中 → 点内部 Circle，Circle 出现橙色虚线框(=Selection 选中框)，但矩形上仍有黑色虚线+方形手柄(=Transform 变换框)，用户判断"Circle 没选中"；点房间则正常。
- 根因（读 X6 源码 + 无头实测）：X6 `Transform` 插件**只监听 `graph` 的 `node:click`（显示/迁移变换框）和 `blank:mousedown`（清空）**。
  - 我们在 `bindPointerSelection` 的捕获阶段 `stopPropagation`+`preventDefault`，原生 `node:click` 不会合成 → Transform 框停在上一个节点。
  - 而 `g.resetSelection([node])` 会触发 `selection:changed`，Selection 的橙色框切到新节点 → **两插件状态不一致**。
- 默认样式对照（用于看截图断案）：`.x6-widget-selection-box` = 橙色虚线 `#feb663`（Selection）；`.x6-widget-transform` = 黑色虚线 + 白底方手柄（Transform）。图里"黑框在矩形、橙框在Circle"就是错位。
- 修复：保存 `transformPlugin` 实例（`registerPlugins` 里 `this.transformPlugin = new Transform({...}); graph.use(...)`），新增 `syncTransformWidget()`：按当前选区主动同步——**单选节点 → `plugin.createWidget(node)`；多选/空选 → `plugin.clearWidgets()`**。在两个接管分支（Ctrl、穿透改选）改完选区后调用。
  - `createWidget`/`clearWidgets` 都是公开方法（d.ts 可见）；`onNodeClick` 是 protected 不能直调。
  - ⚠️ **不要用 `g.trigger('blank:mousedown')` 清空变换框**：Selection 插件也监听它，会连选区一起清掉。
- 验证（headless, 1400x900）：选矩形→点Circle：sel=circle 且 transform.rect 由矩形移到 circle(515,413,80x80) ✅；点房间同理 ✅；Ctrl 多选→变换框隐藏 ✅；拖动正常且松手不跟随 ✅；点空白清空且无变换框 ✅。vue-tsc -b 通过。
- 教训：凡"自研接管并吞掉原生事件"的地方，都要排查**依赖该原生事件的插件**（此处 Transform 依赖 node:click）。以后加/改指针接管逻辑时，改完选区必须同步 Transform。

  - Ctrl/Cmd 命中成员 → 切换"容器"的选中态（组合级多选），逻辑统一到 `unit`。

## 修正：上述方案导致「点击组合里的节点选中不了」（回归）→ 改为"选中成员 + 整组平移"
- 现象（用户反馈）：上一条方案（成员 mousedown → resetSelection([容器]) + 合成 mousedown 打容器）虽然修好了拖动，但**点击组内节点时被选中成了整个容器**，成员永远选不中、属性面板也编不了单个成员。
- 需求澄清：**点击 → 选中鼠标下那个成员本身；拖动 → 移动整个组**。两者必须区分开。
- 最终方案（选择=`node`，位移=`容器`）：
  - `bindPointerSelection.onMouseDown` 命中**成员**（`isMemberOfGroup` = 自身不是容器 且 `findOuterGroup()` 是组容器）→ `resetSelection([node])`（选中成员）+ `syncTransformWidget()`，然后 `beginGroupDrag(最外层容器, clientX, clientY)` 自行接管拖拽。
  - 拖动中对**容器**做 `translate`（容器平移递归带动子节点 = 整组移动）；**绝不能 translate 成员**（成员脱离容器 / 与容器同时动会双倍移动）。
  - 坐标换算用 `graph.clientToLocal(x, y)`（自动跟随画布缩放/平移，别手算 zoom）；每帧按「目标位置 − 当前实际位置」增量 translate，规避 X6 位置取整的累积漂移。
  - 越过 `MOVE_THRESHOLD = 2`（与 Graph 的 moveThreshold 一致）才真正移动，且整段包在 `graph.startBatch('move-group')` / `stopBatch` 里 → 一次拖动只产生一条撤销记录；纯点击不开 batch，不污染 Undo 栈。
  - mousemove/mouseup 挂在 **document**（冒泡），且**不能**在这条分支设 `handled = true`——否则容器捕获阶段的 `stopPropagation` 会挡掉自己在 document 上的 mouseup → 拖动无法结束 → 整组跟着鼠标跑（正是之前踩过的回归）。
  - 例外：该组合**参与多选**（容器已选中且选区 >1）时不接管，放行让 X6 原生拖动整个选区，保留"多选整体移动"。
  - Ctrl/Cmd 分支同步改回切换 **`node`**（成员本身），与普通点击一致，组内成员可被个别多选（贴合既有 `resolveUnits` 里"Ctrl 点选多个成员"的设计意图）。
  - `dispose()` 里先 `groupDragCleanup?.()` 再 `graph.dispose()`，否则收尾的 `stopBatch` 作用在已销毁的 graph 上。
- 行为总表：拖自由节点→只动自身；拖容器/padding→整组；点成员→选中成员（新）；拖成员→整组移动；容器单选时点成员→选中成员（新）；组合参与多选时拖成员→整组选区整体移动（原生）。
- 权衡：自研拖拽期间不触发 Snapline 对齐吸附（X6 的吸附只挂在原生拖拽里），其余（撤销/重做、Transform 跟随、History 单条记录）均正常。
- vue-tsc -b 通过（两轮）。

## bug 修复：Shift+方向键 不生效（连带 Alt+方向键也不生效）
- 根因：X6 Keyboard 插件按"按键 + **精确修饰键集合**"匹配绑定（`u(eventMods, bindingMods)` 做 `sort().join ===` 全等比较）。`bindKey('up', …)` 的绑定修饰键是空集 `[]`，而按住 Shift 时事件修饰键是 `['shift']`、Alt 时是 `['alt']`，与 `[]` 不等 → 回调**根本不触发**。所以"Shift 不生效"和"Alt 整组移动"其实一直都没生效（上一条只修了成员/组路由，没修修饰键匹配）。
- 修复：`bindArrowKeys` 对四个方向各注册三种写法——`up` / `shift+up` / `alt+up`（down/left/right 同理），三者共用同一个 `move` 回调（回调内部自行读 `e.shiftKey` 取大步长、`e.altKey` 取整组）。插件本身支持 `ctrl+z`/`ctrl+shift+z` 这种修饰键绑定写法，故 `shift+up` 能正常匹配。
- 注意：仅覆盖"单修饰键"常见组合；Shift+Alt+方向键（双修饰键 `['shift','alt']`）未单独绑定，属可接受边界情况。
- vue-tsc -b 通过。
- ⚠️ 经验：X6 键盘绑定凡要响应修饰键，**必须在 bindKey 里显式写出修饰键前缀**，不能只靠回调里读 `e.shiftKey/altKey`——否则修饰键变体根本匹配不到。

## 修复：空格平移画布时同时拉出蓝色选框（rubberband）
- 现象：按住空格（`panning.modifiers:['space']`）+ 左键拖动 → 画布在平移，同时出现半透明蓝色选框（`.x6-widget-selection-rubberband`，CSS opacity .3）。
- 根因：X6 `allowRubberband(e, true)` 严格模式走 `isModifierMatch`，**只检查 ctrl/shift/alt/meta**（内部把 `spaceKey` 强制置 false），空格不在检查范围 → 空格按下时框选依然"允许"，与 Panning 各走各的。Selection 自带的 `resolvePanningSelectionConflict()` 只比较 `eventTypes`/`modifiers`，本项目 `options.eventTypes` 为 undefined → 判不出冲突，不会自动禁用平移。
- 方案：`registerPlugins` 里把 Selection 实例存到 `this.selectionPlugin`；新增 `bindSpaceRubberbandGuard()`（仅非预览模式）——document 捕获阶段 keydown/keyup 监听空格，按下 `disableRubberband()`、松开 `enableRubberband()`，`window.blur` 兜底恢复（防止空格按住时切窗导致框选永久失效）；输入框/文本域内敲空格不干预。`dispose()` 里 `spaceGuardCleanup?.()`。
- 不动 Panning：`onMouseDown` 的启动条件是 `allowPanning(t,true) || (allowPanning(t) && !rubberbandAllowed)`，前半段独立成立，框选关闭后平移照常，且 `updateClassName` 会正确加 `x6-graph-pannable/panning` 光标。
- 无头实测（playwright-core + chromium-1234，注意 ESM 不认 NODE_PATH，要用绝对 file:// 路径 + default 导入）：空格拖拽 → viewport matrix 443,399→523,449（位移与拖拽量一致）、panningClass true、rubberband false；松开空格普通拖拽 → rubberband true（框选恢复正常）。

## 新增：缩放快捷键 Ctrl/Cmd + 0 / - / +
- 需求：Ctrl/Cmd+0 重置缩放(100%)、Ctrl/Cmd+- 缩小(-0.2)、Ctrl/Cmd++ 放大(+0.2)。
- ⚠️ 踩坑（X6 键名解析对 "+" 的歧义）：最初用 `g.bindKey(['ctrl++','command++','ctrl+=','command+='], …)` 复用 `transform()`，但**实测 `Ctrl+Shift+=`（主键盘字面 "+"）根本不触发**（`Control+Equal` 无 shift 倒能触发）。读 X6 源码确认：绑定侧 `p()` 会把 "+" 经 `o` map 归一成 "="+shift；但**事件侧 `c(t)` 对 keyCode 187 直接返回 "="，不反向归正 "+"**，且 `handleKey` 用 `u()`（sort 后全等比较修饰键）匹配——导致 `ctrl++`（key="=",mods=[ctrl,shift]）与主键盘 `Shift+=`（key="=",mods=[shift,ctrl]）理论上应匹配，实测却失配（X6 对组合键事件的处理对 "+" 不稳定，小键盘 + 走 keyCode 107→"+" 更是完全对不上）。
- 最终方案（避开 X6 解析）：新增 `bindZoomShortcuts()`，在 `document` 上**捕获阶段**原生监听 keydown，直接读 `e.key`/`e.code` 路由到 `transform()`——
  - `0`/`Digit0`/`Numpad0` → `zoomTo`（重置 100%）；`-`/`Minus`/`NumpadSubtract` → `zoomOut`；`+`/`=`/`Equal`/`NumpadAdd` → `zoomIn`。
  - 覆盖主键盘 `=`、`Shift+=`（字面 +）、小键盘 `+`，以及 numpad `0`/`-`。
  - 输入框（INPUT/TEXTAREA/contenteditable）内不干预；命中后 `preventDefault()` 阻止浏览器页面缩放。
  - 仅非预览模式绑定；`dispose()` 里 `zoomGuardCleanup?.()` 移除监听。
- 复用既有 `transform()`（zoomIn=`g.zoom(0.2)`、zoomOut=`g.zoom(-0.2)`、zoomTo=`g.zoomTo(1)`），自动遵循 scaling 上下限。
- 工具栏（HomeView `commands`）给放大/缩小/重置三项加 `shortcut` 字段（'Ctrl + +'/'Ctrl + -'/'Ctrl + 0'），并用 `el-tooltip` 显示。
- 无头实测（playwright-core + chromium-1234）：Ctrl+=→1.2、Ctrl+-→1.0、Ctrl+Shift+=→1.2、Ctrl+0→1.0，全 PASS。vue-tsc -b 通过。
