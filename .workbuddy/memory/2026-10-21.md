## 组合重构（方案 B：隐形父容器）+ hover 整组高亮
- **重大坑（已修）**：`removeFromParent()` 内部走 `removeChildAt` → `unembed()` 之后还调了 `child.remove()`，会**把子节点真正删除**！取消组合必须用 `parent.unembed(child)`。这是"取消组合后节点全消失"的根因。
- 方案 B：组合仍建父容器，但 `fill/stroke` 设 `transparent`（平时不可见），仍可选中（点击 padding 区选中整组）、拖动时靠 X6 原生 embedding 联动子节点。
- 组合限制：`canGroup` 要求选中节点**全部**无父且无子（杜绝重复/嵌套组合）；`canUngroup` 为选中项含容器或有父的成员。
- 取消组合语义增强：选中组内任一成员即可解散**整个组**（含未选中的兄弟节点），并自动选中释放出来的节点。
- hover 整组高亮：监听 `node:mouseenter/mouseleave`，把隐形容器的 `body/stroke` 切到 `#409EFF` + 淡填充；mouseleave 用 50ms 延迟清除，避免组内节点间移动闪烁。
- `dispose()` 清理 hoverTimer，防泄漏。

## 组合 bug 修复：框选混入隐形容器导致菜单误判
- **现象**：已组合后再框选新节点，右键显示【取消组合】（应为【组合】）。
- **根因**：橡皮筋框选按几何相交计算（`getCellsInArea`），隐形容器包围着成员，框选必然连容器一起选中 → `canUngroup` 误判为 true。
- **为何不用 Selection 的 `filter` 排除容器**：框选走 `reset()` → `filter()`，而 `filter` 同时作用于点击选中和 `graph.select()`，排除后容器将完全无法选中（也就无法拖动整组）。
- **解法（选区智能判定）**：`buildMenuState` 把选区分成"自由节点"（无父无子）和"已分组的"（容器/成员）：`canGroup = free.length >= 2`；`canUngroup = free.length === 0 && grouped.length > 0`。容器被排除在组合之外。
- `groupSelection()` 相应改为只组合选区中的自由节点；菜单文案显示 `组合 (N)`（N = freeCount），让用户清楚会组合几个。
- 附带确认（**此结论有误，已更正**）：`Cell.remove()` 内部有 `if (options.deep !== false) this.eachChild(child => child.remove(options))`，**默认就是递归删除子节点**。删容器会连带删光组内成员；想"只删容器保留子节点"必须先 `unembed` 全部子节点再删（这也正是 `ungroupSelection` 的写法）。

## 组合逻辑再修正：递归删除 + 支持"组合 + 新节点/组合"合并
- **递归删除**：`GraphEditor` 新增 `collectDeep(cells)`（用 `getDescendants()` 收集所有后代，默认 deep=true）。`removeSelected()` 改为先 `collectDeep` 再 `removeCells`；Delete 快捷键也改走 `removeSelected()`，行为统一。连边由 X6 自动清理（`model.unreference()` 会 `removeConnectedEdges`），无需手动处理。
- **组合判定改为按"单元"计数**：一个已有组合（容器本身，或成员所属的父容器，按 id 去重）= 1 单元；一个自由节点 = 1 单元。`canGroup = unitCount >= 2`、`canUngroup = freeCount === 0 && groupCount > 0` → 「组合 + 1 个新节点」现在正确显示【组合】。
- **合并组合**：`groupSelection()` 重写——旧容器 `unembed` 全部成员后删掉（此时容器已空，不会误删成员），成员 + 自由节点一起并入新建的隐形容器。
- `ContextMenuState` 新增 `groupCount` / `unitCount` / `removeCount`；菜单 `组合 (N)` 用 unitCount，`删除 (N)` 用 removeCount（含后代，避免少报）。
- 验证：`vue-tsc -b` 与 `vite build` 均通过（exit 0）。

## 取消组合最终语义：只解除「选中项」的组合关系（用户明确确认）
- 选中**成员** → 只把它自己 `unembed` 移出组，组内其他成员仍成组；菜单文案「移出组合」。
- 选中**容器** → 解散该容器这一层，直接子节点整块释放（嵌套子组保持成组）；菜单文案「取消组合」。
- 移出后剩余成员 < 2 → 该组自动解散（单成员组无意义，且会留下隐形空框）；剩余 ≥ 2 → `fitContainer()` 用 `getCellsBBox` 重新贴合包围盒，避免容器框住空区域。
- `ContextMenuState` 新增 `hasContainer`，HomeView 据此在「取消组合 / 移出组合」间切换文案。
- 中间曾按「只剥最外层（findOuterGroup → 根容器）」实现过一版，用户反馈仍是"全部取消"→ 弃用。教训：用户说的"一层"指的是**选中项这一层**，不是层级树的一层。
- 容器尺寸要随成员变化维护：`container.position(x,y)` + `container.size(w,h)`。
- `ungroupSelection()` 重写：新增 `findOuterGroup(node)` —— 用 `getAncestors()`（返回 [直接父, …, 最外层]）取**最后一个**即根容器；每个选中节点都归到所属的最外层容器再解散。
- 效果：从外向内剥，只解散最外一层；内层嵌套组整块保留为独立组；框选同时命中外层容器和内层成员时归到同一个根容器，只解散一次。
- `unembed` 只切断直接父子关系，子节点自带的子树整块保留 → 内层嵌套组不会被连带打散。
- 坑：`Cell.remove()` 内部会 `setParent(null)`，所以祖先链必须在删除前取好，删完就取不到了。
- `isDescendantOf` / `getAncestors` / `getDescendants` 默认 `deep: true`（源码 `options.deep !== false`），会遍历整条链，无需显式传参。
