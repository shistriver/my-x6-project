# 2026-10-22

## 组合/取消组合：改为真正的层级模型（用户给的目标形态）
用户明确目标：`组A={n1,n2}`、`组B={n3,n4}`、`组C={组A, 组B, n4}`，取消组合 C 应得到 `组A、组B、n4`。

### 组合（groupSelection）改为**嵌套**而非打散
- 旧实现：合并时把旧容器 unembed 成员后删除，成员平铺进新容器 → 画布上永远是单层，`组C={组A,组B,n4}` 这种结构根本不存在，也就谈不上"取消最外层"。
- 新实现：新容器的直接子节点 = **最外层旧组容器（整块）** + 自由节点；用 `isDescendantOf` 过滤掉"是其他候选后代"的内层组，避免重复挂载。
- `insertChild` 内部自动先摘旧父再挂新父（且不删除节点），所以 `parent.addChild(旧容器)` 是安全的，不用手动 unembed。

### 取消组合（ungroupSelection）的关键：跳过被解散容器的子树
- 框选 C 时选区必然同时含 C、A、B 和全部成员。若不处理，会一边解散 C、一边把选中的成员逐个移出 A/B，导致 A、B 被掏空 → 用户看到的"全部取消"。
- 解法：先算出 `dissolved`（选中的容器里的最外层），成员过滤条件加 `!dissolved.some(c => n.isDescendantOf(c))`，位于被解散子树内的选中项随子树整块释放。
- 选中容器 → 解散该层，直接子节点整块释放（嵌套子组保持成组）；选中成员 → 只移出它自己。
- 级联整理：`touched` 里容器剩余成员 < 2 时自动解散，并把它的父容器加入 `touched`（Set 遍历覆盖后加项），最终往上逐级 refit 或解散。
- 容器 refit：`fitContainer()` 用 `getCellsBBox` + `container.position/size` 重新贴合，pad=16。

### 教训
用户说的"一层"经历过三次误读：① 层级树的一层（findOuterGroup 剥最外层）② 选中项这一层 ③ 最终是「组合时保留嵌套，取消时释放整块」。定位这类问题要让用户给**具体的前后状态**（如 C={A,B,n4} → A、B、n4），而不是抽象描述层级。

## 对齐/方向键以「组合」为单位
- 需求：框选 [组合 + 自由节点] 对齐时，组合要算**一个整体**（用整组包围盒对齐），而不是成员各自对齐（此前 New Hello X6 会被单独挪进两节点中缝，错位）。
- `alignSelection` 重写：选中的节点先归并成"单元"——`findOuterGroup(n)`（`getAncestors()` 取最后一个 = 最外层容器；自由节点即自身），Set 去重；单元 < 2 直接 return（同一组合内部成员间不对齐）。移动单元用 `translate`，**容器平移时子节点原生跟随**（源码：`Node.translate` 非 transition 分支 `eachChild(child => child.translate(tx,ty))` 递归平移子树）。
- 顺带修方向键同类 bug：框选选中"容器+成员"时，容器和成员各自 translate 会**双倍移动**成员；`bindArrowKeys` 同样先归并单元再移动。
- `findOuterGroup` 恢复为私有方法（ungroup 重写时曾删掉，现在对齐/方向键/取消组合三处共用根容器语义）。

## 文字节点：拖入画布后按内容自适应宽高
- 需求：左侧 Text 节点拖入画布后，节点宽高自动贴合文字内容。
- 识别方式：在 `shapes.ts` 的 text 项 `meta` 上加 `data: { isTextNode: true }`（显式标记，不靠"透明 body"猜），并给 label 显式 `fontFamily: 'sans-serif'`，使测量与渲染字体一致。
- `GraphEditor` 新增 `isTextNode()` / `measureTextSize()` / `fitTextNode()`：用离屏 canvas `measureText` 测真实渲染宽高（含 CJK 宽度、按 `\n` 多行），加少量内边距后 `node.resize()`；并用 `graph.zoom()` 换算，保证任意缩放级别下落图都贴合（节点尺寸是画布坐标系，measureText 是屏幕像素，二者仅在缩放=1 一致）。
- 触发时机：① 落图 `node:added`（用既有 `pendingDropId` 识别）→ 自动 fit；② `applyNodeProps` 里 label 或 fontSize 改动时 → 自动 re-fit（手动改宽高不触发，避免覆盖用户意图）。
- 兜底：无法创建 canvas 时退化为"字符数 × 字号"估算。

## 修复：拖入后框选框比文字小（文字节点自适应失效）
- 现象：Text 拖入后选框约 30×24（宽高比 ≈1.25），远小于文字。

- 修复：新增 `readNodeLabel/readNodeFontSize/readNodeFontFamily` 三个双路径读取辅助（`text/...` 优先、兼容 `label/...`）；`fitTextNode` 改用它们；`applyNodeProps` 的 label 写入改为 canonical `text/text`；快照的 label/fontSize/fontFill 也走双路径读取。
- 验证依据：截图选框宽高比 ≈1.44 ≈ 30/24（最小尺寸兜底），而非 120/40=3.0（未 fit）→ 说明 fit 已执行、`data.isTextNode` 经 Dnd 双重 clone 仍存活，仅是文字读空。

### wall-l 选中问题修复
- 现象：L 形墙选中"框和墙对不齐"。读 X6 源码证明渲染无错位（refDy=相对底边 corner 偏移、refHeight:1=100%、选中框=几何 bbox），截图虚线框其实是**橡皮筋**。

- 遗留限制：橡皮筋框选按 model bbox 相交（`getNodesInArea` → `isIntersectWithRect`，Selection 无 per-node 命中钩子），碰到 L 包围盒空白角也会选中——X6 画布对非矩形形状的通用行为，无法按可见形状过滤，已向用户说明。

### wall-l 选中框下边缘穿底臂（第二次，真正的定位错误）
- 用户再报"还是有问题"：截图里选中/缩放框的**下边缘从底臂中间穿过、底臂明显伸出框外**。此前判断"渲染无错位"是错的，确实有两臂溢出几何 bbox 的问题。
- 读 `registry/attr/ref.js` 确认 `setWrapper`/`positionWrapper` 语义：
  - `refWidth`/`refHeight`：**只有 0~1（或百分比）才是"占参考框比例"**；值 `<0` 或 `>1` 时算成 `value + refBBox[dimension]`（"框尺寸 + 值"）。所以旧值 `refHeight:4 → 4+60=64`（左臂高 64，向下溢出 4）、`refWidth:4 → 64`（底臂宽 64，向右溢出 4）。
  - `refDy` 基准是**右下角（corner）**：`refDy:0 = 底边上`，再叠 `height:4` → 矩形从 `y=H` 往下画到 `H+4`，整条底臂落在框外 4px——正是截图现象。
- 修复：左臂 `refHeight:4 → 1`（占满 100%）、底臂 `refWidth:4 → 1` + `refDy:0 → -4`（底边往回偏一个墙厚）；厚度仍走绝对像素 `width:4`/`height:4`，与直线墙一致。两臂均落在 `[0,W]×[0,H]` 内，选中框/缩放框正确包住可见 L。`npm run build` 通过。

### 直线墙 / L 形墙 描边不一致 + 对不齐（bug）
- 根因：`GraphEditor.ts` 里 `isWall` 只判 `SHAPE_WALL_L`，**直线墙（`wall-line`）没被当成墙**：
  - 面板：wall-line 是普通矩形 → 显示「描边色/描边样式/描边宽度」，而 wall-l 隐藏这些 → 两者字段不一致（用户说的"描边大小不一致"）。
  - 墙厚：wall-line 粗细 = 几何**高度**（靠「高」调），wall-l 臂粗写死 4px **无任何字段可改** → 二者无法设成相同粗细，拼接不对齐。
- 修复（用户选了「统一面板+墙厚控件」与「改包围盒/吸附对齐」两个方向）：
  - `isWall` 改为同时覆盖 `SHAPE_WALL_L` 和 `SHAPE_WALL_LINE` → 两种墙面板一致（都隐藏内容+描边，只显示填充色+尺寸）。
  - 新增 `NodeSnapshot.wallThickness` / `NodePropsPatch.wallThickness`，面板加「墙厚」控件（`:min=1 :max=20`）：
    - wall-l：`applyNodeProps` 把厚度下发到 `wV/width`、`wH/height`、`wH/refDy(-t)`（底臂仍贴底，避免再次溢出）。
    - wall-line：厚度 = 几何高度 → `node.size(width, t)`；面板对 wall-line **隐藏「高」**（高即墙厚，避免重复）。
  - 取值：`getSelectedNodeSnapshot` 墙厚 wall-l 读 `wV/width`、wall-line 读 `size.height`；填充色 wall-l 读 `wV/fill`、wall-line 读 `body/fill`。
- 对齐（包围盒/吸附）：wall-line 盒子即实心条（已贴合墙身），wall-l 盒子=可见 L 的整框（L 占满 60×60，已贴合）；两种墙厚度统一后，拼接时按**边缘吸附**即可让墙身对齐（直线墙盒子=墙、L 形墙底/左臂在盒子底边/左边）。`npm run build` 通过。
- 说明：X6 矩形包围盒只能是矩形，L 形透明内角无法消除，因此无法做到"按墙中心线吸附"，需自定义 snap 才算严格对齐——本次未做，已可手动边缘对齐。

## 两种墙「描边大小不一致 / 对不齐」修复（第 2 轮）
- 用户截图：L 形墙底臂明显比直线墙粗、底边不齐。
- 根因：墙厚的修改通道不一致——wall-l 的两臂厚度 Transform 缩放永远不改（ref 绝对像素），只能面板改；wall-line 的厚=几何高，Transform 拖上下手柄就能改 → 两种墙厚度很容易被拖歪、对不上。
- 修复：Transform 插件 `resizing` 选项支持函数值（`parseOptionGroup` 按节点解析，widget 每次 node:click 重建）：wall-line 的 `minHeight = maxHeight = node.getSize().height` 锁死墙厚，拖上下手柄不再变厚；其他节点返回 0（源码 `minHeight || gridSize` 回退默认网格下限，行为不变）。墙厚现在唯一入口是面板「墙厚」。
- 关键源码依据：transform/index.js `parseOptionGroup`（typeof val === 'function' → val.call(graph, arg)）、transform.js:275-278 拖拽中钳制、widget 每次 node:click 重建保证钳制值新鲜。
- 对齐：墙厚一致后 snapline 的边/中心吸附三线重合，拖到 L 臂端点即齐。

### 编号房间「文字框是空的」bug 修复
- 现象：拖出编号房间（room-number），右侧面板「文字」框空白，画布上却显示默认编号 "79/80"。
- 根因（无头 chrome + 真实 GraphEditor 实跑验证）：room-number 注册表在 `attrs.label` 里**写死了默认编号 `text: '79\n/\n80'`**；而调色板 meta 用 `label: ''` 落图。X6 的 `Base` propHooks 把顶层 `label` → `attrs/text/text`，所以 `attrs/text/text` 被写成空串 `''`。`readNodeLabel` 先读 `attrs/text/text`，`''` 是 string 就直接返回空，永远不会回退到注册表的 `attrs/label/text` 默认 —— 面板因此空白。
- 关键规律：**编号这类要在面板编辑的文字，默认必须走顶层 `label`（→ canonical `attrs/text/text`），绝不能写死进注册表的 `attrs.label.text`**（后者会被 `label:''` 落图时覆盖成空）。
- 修复：
  - `shapes.ts` room-number 注册的 `attrs.label` 删掉 `text: '79\n/\n80'`（只留样式：fill/fontSize/定位）。
  - 调色板 room-number 项的 `meta` 改成 `label: '79\n/\n80'`（默认编号走 canonical 路径）。
  - `readNodeLabel` / `applyNodeProps` 不动（本来就正确读/写 `text/text`）。
- 验证：实跑 `g.createNode(paletteMeta)` → 快照 `label='79\n/\n80'`（不再空）；`applyNodeProps({label:'101\n/\n102'})` 后 `node.attr('text/text')` 同步更新（画布+面板一致）。`vue-tsc -b` 通过。
- 注意：room-number 还有第二个文字元素 `area`（"20m*30m"，注册表 `attrs.area.text` 写死），面板未暴露，目前仍是固定占位；若要可编辑需扩快照+面板（本次未做）。

### 编号房间「面积标注（area）」面板可控显示+编辑
- 需求：room-number 的第二个文字元素 `area`（selector `area` 的 `<text>`）要能在属性面板**改内容**、并**开关显隐**。
- 实现（已实跑验证）：
  - `shapes.ts`：room-number 注册表 `attrs.area.text='20m*30m'` 保留作默认值（仅样式+默认内容，非写死覆盖用户值）。
  - `GraphEditor.ts`：`NodeSnapshot` 新增 `areaText: string` + `areaVisible: boolean`；`getSelectedNodeSnapshot` 仅对 `SHAPE_ROOM_NUMBER` 读取 `node.attr('area/text')`（兜底空串）与 `node.attr('area/display') !== 'none'`；`applyNodeProps` 仅对 room-number 写回：`areaText` → `node.attr('area/text', v)`，`areaVisible` → `node.attr('area/display', visible ? null : 'none')`（`null` 删属性=默认可见）。
  - `PropertyPanel.vue`：form 加 `areaText/areaVisible`；watch 回填；新增「面积标注」子区，用 `v-if="snapshot.shape === 'room-number'"` 仅对编号房间显示：一个 `el-switch`（显示/隐藏，下发 `areaVisible`）+ 一个 `el-input textarea`（面积文字，禁用态跟随开关，下发 `areaText`）。开关关掉时 textarea `:disabled`。
- 验证依据（无头 chrome 实跑真实 GraphEditor）：
  - 落图快照 `areaText='20m*30m'`、`areaVisible=true`（读正确）。
  - `applyNodeProps({areaVisible:false, areaText:'99m*88m'})` → `area/display='none'`、`area/text='99m*88m'`（写正确）。
  - 单独验证 `attrs.area.display='none'` 时渲染层 `<text display="none">` → 画布真隐藏（SVG presentation attr 生效）。
  - 关键认知：room-number 的 markup 用 selector `label` 的 `<text>` 渲染**编号**，但内容走 canonical `attrs/text/text`（由顶层 `label` 元数据经 propHook 写入）→ 所以编号既能在画布显示、又能被 `readNodeLabel` 读到，两者互不冲突；`area` 是独立 selector，自成一套 `area/text` + `area/display`，与编号路径完全解耦。
- `vue-tsc -b` 通过。
