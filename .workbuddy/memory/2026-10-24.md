### 修改：预览 Scroller 滚动范围收紧（padding:0）
- 现象：预览滚动条滑块很小、滚动范围远大于内容（大量空白可滚）。
- 根因：X6 `Scroller` 默认 `padding()` 返回四边留白 `max(视口尺寸-50, 0)`，导致滚动内容区被撑大成"视口+巨量空白"，滑块很小。
- 实现：`init(preview)` 预览分支 `new Scroller({ pannable: true, padding: 0 })`。`padding:0` 经 lodash `merge` 覆盖默认函数（值类型优先），`getPadding()` 返回全 0，`addPadding` 不再给内容区加留白 → 滚动区恰好等于内容包围盒。
- 注意：Scroller 自身不绑定 wheel 缩放（无 mousewheel 选项），滚轮走原生 `overflow:auto` 滚动；已 `disableMouseWheel()` 关掉 X6 缩放，故滚轮=滚动、非缩放。内容小于视口时无法靠滚动居中（scrollLeft 不能负），会停在左上角——属可接受（用户诉求是"滚动刚好包住内容"）。
- 验证：`vue-tsc -b` 通过（exit 0）。

### 修改：预览 Scroller 宽度/滚动范围过宽（真实根因 + 彻底修复）
- 现象（二次反馈）：即便 `padding:0`，预览横向滚动范围仍远大于内容（"Scroller 宽度太宽"）。
- 真实根因：X6 `ScrollerImpl.addPadding()` 在 `center()`/`positionContent()`/`onResize()` 时，会把"居中需要的留白"累加到内容区宽度（`content.style.width = padding.left + graphW + padding.right`），且 `this.padding` 持久化、每次 resize 又经 `centerPoint` 重新累加 → 滚动区被反复撑大。仅设 `padding:0` 只清了基准，堵不住 `center/onResize` 的追加。`init()` 在空画布阶段 `center()` 也会基于容器尺寸虚增。
- 修复：
  1. 把 Scroller 创建从 `init(preview)` 移到 `loadJSONForPreview`（数据加载后再挂载，避开空画布 `center()` 虚增）。
  2. `init` 预览分支只保留锁定（disableSelection/Rubberband/MouseWheel + interacting=false）。
  3. `loadJSONForPreview` 挂载 Scroller 后，重写 `impl.addPadding` 为"内容区宽高 = graph 尺寸 + 0 留白、container left/top = 0"，彻底中和居中/resize 追加的留白；随后 `impl.update()`（fitToContent 让 graph 尺寸=内容包围盒，padding:0 + allowNewOrigin:'negative'）+ 手动 `impl.addPadding(0,0,0,0)` 落地尺寸 + 滚动复位到左上。
- 机制确认：`graph.resize`（来自 `observeContainer` 的 ResizeObserver）在 Scroller 存在时委托 `scroller.resize`→设视口尺寸+`update()`；其发出的 `resize` 事件触发 `onResize→centerPoint→addPadding`，因已被重写为无追加，resize 不再撑宽。滚轮=原生滚动（Scroller 不绑 wheel 缩放，X6 缩放已 disable）。
- 验证：`vue-tsc -b` 通过（exit 0）；dev server 在 http://localhost:5175/ 供人工验证。

### 大改：预览改用 zoomToFit 自适应居中，彻底弃用 Scroller
