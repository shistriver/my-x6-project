### 2026-10-23 续：修复"组合旋转有问题"（用户带截图反馈）
根因有 **3 个叠加**，都在上一轮实现里：
1. **双旋转**：框选组合时必然同时选中隐形容器 + 它的成员（橡皮筋按 bbox 相交判定），而 X6 Transform 对**每个选中 cell** 各应用一次旋转 → 成员被 Transform 转一次、又被组合传播转一次 = 60°。→ 新增 `bindSelectionNormalize()`/`normalizeSelection()`：`cell:selected`/`cell:unselected` 后 `queueMicrotask` 归并，若容器与后代同时选中则只保留最外层容器（`getAncestors()` 判定），`normalizingSelection` 防重入。
2. **⚠️ X6 `rotate(angle,{center})` 自带 bug**（v3.1.8 `model/node.js` 的 `rotate`）：内部用 `center.rotate(currentAngle - angle, center)`，节点**已带角度**时实际转角变成 `angle - currentAngle`（30° 的节点再转 45° 只转 15°）。第一次旋转 `currentAngle=0` 恰好正确，所以"转一次对、转两次歪"。→ 新增 `rotateNodeAround(node, delta, center)`：自己算中心绕点旋转 + `node.rotate(delta)` 只加角度，**不要用 X6 的 `rotate(...,{center})` 传播**。
3. **fitContainer 不认旋转**：容器带 angle 时仍按轴对齐 bbox 设 position/size → 旋转框整体错位、且 `getCellsBBox` 不含角度导致框偏小包不住。→ 重写 `fitContainer`：用 `nodeCorners()` 取成员**旋转后真实角点**，逆旋转到容器自身方向取最小包围矩形，再把该矩形中心转回世界坐标作为容器中心；angle=0 时自动退化为旧行为。同时 `node:change:angle` 里**成员自身旋转也 refit 父容器**（原来只处理容器，成员单独旋转时框不跟）。`groupSelection` 建组后也调 `fitContainer` 补一次（成员可能已旋转）。
- 验证（无头 Chrome 实跑真实 GraphEditor）：框选容器+成员 → 选区归并为 `[CONTAINER]`；旋转 30°→成员 angle 恰好 30（非 60）；连续转 30°→75°、旋转中改尺寸/移动成员、成员单独转 45°、容器回正 —— 所有场景容器局部系下四边 pad 均 = 16 且 `inside=true`。
- 经验：Transform 真实路径是 `node.rotate(target, { absolute: true })`（只改角度不改位置，见 `plugin/transform/transform.js:397`），与增量监听兼容；`rotate(...,{center})` 只被我方调用，已替换为自研实现。

### 2026-10-23 续：修复"点击节点时，会触发位置改变"
- 根因（X6 v3 关键行为）：Graph 默认 `moveThreshold: 0`、`clickThreshold: 0`。X6 的这两个阈值是**鼠标移动事件的次数**（不是像素）：`onMouseMove` 里 `mouseMovedCount <= moveThreshold` 时**不开始拖拽**，默认 0 意味着只要出现 1 次 mousemove 就立刻开始拖拽。真实点击几乎都伴随 1~2 次指针抖动（mousemove），于是被当成"拖动开始"，节点（组内子节点还会带着隐形容器一起）被移动 → 用户看到"点击节点就改变位置"。
- 修复：在 `new Graph({...})` 选项里设 `moveThreshold: 2` 与 `clickThreshold: 2`。`moveThreshold: 2` → 前 2 次 mousemove 不触发拖拽，纯点击/轻微抖动不再移动节点；`clickThreshold: 2` 必须同步设（否则抖动点击因 `mouseMovedCount>0` 而 `cell:click` 不触发 → 节点无法选中）。两者一致：≤2 次 mousemove = 点击（选中、不移动），>2 次 = 真拖动（移动）。取值 2 而非 1 是为了覆盖更多抖动场景；真拖动通常产生数十次 mousemove，不受影响。
- 验证：`vue-tsc` 通过。X6 源码确认机制（`graph/view.js` 的 `onClick`/`onMouseMove` + `graph/options.js` 默认 0）。注：无头合成事件无法可靠触发 X6 拖拽会话（会话数据不跨合成事件传递），故改用源码核对 + 类型检查，未在浏览器实跑拖拽（已在回复中说明，建议用户硬刷新后实测）。
