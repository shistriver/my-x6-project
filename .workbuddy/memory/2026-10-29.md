## BUG 修复：画布缩放时参考线/标尺不跟随
- 现象：放大/缩小画布时，参考线与标尺刻度不重新定位（错位）。
- 根因：参考线/标尺重绘监听了 `'graph:transform'` 与 `'graph:resize'`，但 X6 v3 的视口事件名是**无前缀**的 `scale` / `translate` / `resize`（`graph:transform` 根本不存在，监听了也不触发）。X6 源码 `graph/transform.js` 用 `this.graph.trigger('scale'|'translate'|'resize', ...)`，官方 background/grid 插件也是用 `g.on('scale'/'translate'/'resize', ...)` 监听。
- 修复：`initGuides()` 与 `attachRulers()` 里把 `graph:transform` → `scale`+`translate`，`graph:resize` → `resize`（两个都监听，覆盖缩放+平移+容器尺寸变化）。
- ⚠️ 坑：X6 v3 视口/变换事件没有 `graph:` 前缀；cell 事件才有 `node:`/`blank:`/`cell:` 前缀。以后涉及视口重绘监听一律用 `scale`/`translate`/`resize`。
- `pnpm run build` 通过。

## BUG 修复：属性面板改文字/样式后点画布，修改丢失（节点上不显示）
- 现象：在属性面板「文字」输入框输入内容（或改样式），点击画布后，节点的文字/样式没生效。
- 根因：`applyNodeProps()` 原本只对「当前单选中节点」写属性（`getSelectedCells().filter(...).length === 1` 才执行）。而属性面板文字框用 `@change`（**失焦才下发**）；点击画布空白会**先**由 X6 Selection 插件清掉选区（`blank:mousedown` → `selection:changed` 同步触发），**之后**输入框失焦的 `@change` 才触发 `apply`——此时选区已空，`applyNodeProps` 直接 return，修改从未写进节点。`bindPointerSelection` 对空白直接放行，清选区是 X6 默认行为。
- 修复：新增 `lastSelectedNodeId` 字段（在 `getSelectedNodeSnapshot` 命中节点时记录；**选区清空时故意不清空**）。`applyNodeProps` 改为：优先用当前单选中节点；若无单选中但存在 `lastSelectedNodeId`，则按 id 取节点写回。这样「先清选区、后失焦下发」也能命中正确节点。切到别的节点时该 id 会被覆盖，不会定位错节点。
- 注意：多选批量样式（`applyMultiStyle`）走 `getSelectedCells` 也有同类竞态风险，但本次只修了单选文字/样式这条上报路径，多选未动。
- `pnpm run build` 通过。

## BUG 修复：文字节点拖入画布松开后位置跳动
- 现象：从左侧面板拖「文字」节点到画布，鼠标松开后，节点位置相对落点偏移（肉眼跳位）。
- 根因：X6 内置 `Dnd` 落点把「节点中心」对齐到鼠标（`drop()` 里 `position = clientToLocal(鼠标) - 尺寸/2`）。落图后 `node:added` 触发 `fitTextNode()` → X6 `resize()` 默认保持**左上角(origin)不动、只改尺寸**（direction 为空走 `getOrigin()` 固定点）。文字节点 meta 初始 120×40 与按文字自适应尺寸不一致 → resize 后中心偏移 `(新尺寸-旧尺寸)/2` → 节点跳位。
- 修复：`fitTextNode()` 在 `resize` 前后保持节点中心不变——先记旧中心 `node.getBBox().getCenter()`，resize 后再 `node.translate(oldCenter - newCenter)`。覆盖拖放落点 + 面板改文字/字号两类调用，行为统一（文字节点始终围绕落点/原中心，不会乱跳）。translate 发生在 dnd batch 内，整次拖放 + 居中位移合并为一条撤销。
- `pnpm run build` 通过。

## BUG 修复：节点拖入画布后高亮，点击不变选中状态
- 现象：从左侧拖节点到画布，松手后节点是"高亮"（橙色 `.x6-widget-selection-box`），但点击它不会变成"真正选中"（黑色变换框/手柄不出现），看起来没选中。
- 根因（查 X6 源码确认）：
  1. X6 的 `.x6-widget-selection-box` 是普通 div，默认 `pointer-events:auto`，节点一选中就盖在它的 bbox 上。点击该节点实际落在覆盖层上，而覆盖层不在节点 view 的 DOM 内，且无 `data-cell-id`；X6 的 cell 事件委托靠 `e.target.closest('[data-cell-id]')` 找 cell，所以 `cell:mousedown`/`cell:mouseup`/`node:click` 全部合成不了。
  2. 因此 X6 的 Transform（只认 `node:click` 显示黑框）和 Selection（`cell:mouseup` 才 `reset`）对这次点击毫无反应。
  3. 叠加：`node:added` 里 `g.select(node)` 后漏调 `syncTransformWidget()`，拖入是"直接建选区、没有点击"，黑框本就不出现。
- 修复：
  - `node:added`（`g.select(node)` 后）补 `syncTransformWidget()` → 拖入即刻进入完整选中态（橙框+黑框）。
  - 自研 `bindPointerSelection` 新增分支：普通点击「已在选区内的节点」（无 Ctrl、无 Alt 整组拖）时，手动 `syncTransformWidget()` + `container.focus()`；不拦截事件（不 preventDefault），避免破坏穿透与拖动。覆盖层挡住 X6 时由自研兜底同步变换框，覆盖层可穿透时 X6 原生仍正常。
- `pnpm run build` 通过。
